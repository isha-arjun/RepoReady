
# Contributing to RepoReady

Thanks for your interest in contributing to RepoReady! 🚀

RepoReady aims to make open-source projects easier for new users to understand, install, and explore. Contributions of all experience levels are welcome.

## What You Can Contribute

Here are some ways to help:

- **Bug fixes:** Fix incorrect checks, broken links, UI issues, or unexpected behavior.
- **New checks:** Suggest useful ways to evaluate a repository's first-time-user experience.
- **Documentation:** Improve explanations, setup instructions, and examples.
- **Accessibility:** Make the interface easier to use with keyboards, screen readers, and different devices.
- **Design:** Improve readability, responsive layouts, and the overall user experience.
- **Testing:** Test RepoReady against different public repositories and report reproducible problems.
- **Ideas:** Propose features that make the tool more useful without making it unnecessarily complicated.

## Before Opening an Issue

1. Check existing issues to see whether the problem or idea has already been discussed.
2. Explain the problem clearly and include an example where possible.
3. For bugs, describe the steps needed to reproduce the issue.
4. For feature requests, explain who would benefit and why.

For substantial changes, open an issue first so we can discuss the approach before you spend time implementing it.

## Making a Contribution

1. Fork the repository on GitHub.
2. Create a branch for your changes.
3. Make a focused change related to one issue or improvement.
4. Test your changes in a modern browser.
5. Review your changes for mistakes and unintended effects.
6. Submit a pull request with a clear explanation of what changed and why.

You can use GitHub's web interface for simple documentation edits. For larger code changes, use a development environment that lets you test the application properly.

## Code and Design Guidelines

Please keep contributions:

- **Simple:** Prefer straightforward solutions over unnecessary complexity.
- **Useful:** Prioritize improvements that help actual users.
- **Accessible:** Maintain readable text, clear contrast, keyboard usability, and responsive layouts.
- **Consistent:** Follow the existing HTML, CSS, and JavaScript patterns where practical.
- **Honest:** Clearly explain what each check measures and what it cannot verify.

RepoReady currently uses plain HTML, CSS, and JavaScript. Please avoid adding frameworks, dependencies, or external services unless there is a clear benefit.

## Requirements for New Checks

New repository checks should:

- Evaluate a specific, explainable aspect of the first-time-user experience.
- Provide a useful explanation when a check passes or fails.
- Avoid claiming to verify something the tool has not actually tested.
- Account for reasonable variations in repository structure where practical.
- Include relevant test cases or reproducible examples.
- Avoid unfairly penalizing projects simply because they use a different language or project structure.

Remember: a readiness score is a heuristic, not a definitive measure of software quality.

## Pull Request Guidelines

Every pull request should include:

- A clear title.
- A short description of the problem or improvement.
- A summary of the changes made.
- Testing performed and any known limitations.
- Screenshots for significant visual changes, where useful.
- A reference to the related issue, if one exists.

Keep pull requests focused. Smaller changes are generally easier to review.

Submitting a pull request does not guarantee acceptance. Changes may require revisions or further discussion before merging.

## Community Expectations

Please be respectful, constructive, and open to feedback.

- Critique ideas and code, not people.
- Explain disagreements calmly.
- Respect other contributors' time.
- Do not submit spam, copied work without appropriate permission, or deliberately misleading changes.
- Never include passwords, access tokens, private repository data, or other secrets in issues or pull requests.

## Questions?

If you're unsure whether a contribution fits the project's direction, open an issue and explain your idea.

Thank you for helping make RepoReady more useful for the open-source community! 💜
